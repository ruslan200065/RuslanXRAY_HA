# Ruslan Xray Gateway

VPN-шлюз для **Home Assistant OS**. Устройства на выделенном Ethernet-порту или отдельной Wi-Fi сети выходят в интернет через Xray. Управление доступно из Home Assistant через Ingress.

## Что понадобится

- Home Assistant OS на **amd64** или **aarch64** с доступом к магазину приложений.
- Отдельный Ethernet-порт или Wi-Fi-интерфейс для клиентов. Wi-Fi адаптер должен определяться в HAOS и поддерживать режим AP через `nl80211`.
- Полный Xray JSON с VPN-выходом или ссылка на подписку Remnawave с выдачей Xray JSON.
- Резервная копия HAOS и доступ к хосту через WAN или локальную консоль.

## Первый запуск

1. В блоке **Профили** нажмите **Добавить**. Вставьте ссылку на подписку и загрузите каталог или импортируйте полный Xray JSON. Для ссылки на готовый JSON отключите добавление `/json`.
2. Выберите профиль. Кнопка **Пинг** измеряет время до HTTPS-ответа от `www.gstatic.com` через конфигурацию профиля. Проверка доступна до включения шлюза. При маршрутизации по правилам профиля запрос может идти напрямую.
3. Откройте **Настройки сети**. Выберите режим раздачи и выделенный клиентский интерфейс. Для Ethernet с DHCP можно оставить адрес `192.168.50.1/24` и предложенный пул, если они не пересекаются с основной сетью.
4. Сохраните настройки, нажмите **Включить шлюз** и подключите тестовое устройство. Проверьте его доступ в интернет и внешний IP.

Каждый запрос подписки передаёт обязательный заголовок `X-HWID`. Новая установка получает свой UUID. Идентификатор хранится в данных приложения, поэтому при перезапуске и обновлении сохраняется. При восстановлении из резервной копии восстанавливается прежний HWID.

| Режим | Когда выбрать | Как подключить клиентов |
| --- | --- | --- |
| Ethernet / IP + DHCP | Есть отдельный Ethernet-порт | Подключите клиент, коммутатор или внешнюю точку доступа к выделенному порту. На внешней точке включите режим AP/моста и отключите DHCP. |
| Wi-Fi AP | HAOS видит адаптер, драйвер поддерживает AP | Выберите Wi-Fi-интерфейс, задайте SSID, пароль WPA2, диапазон и канал. После запуска подключитесь к новому SSID. |
| Ручная настройка | Клиентский адрес и DHCP уже настроены отдельно | Назначьте клиентскому интерфейсу IPv4 из поля шлюза в HAOS и раздайте этот адрес клиентам как шлюз. |

## Маршрутизация и ограничения

- Xray перехватывает публичный IPv4 TCP/UDP на выделенном интерфейсе через nftables TProxy. Пересылка остальных пакетов с этого интерфейса блокируется, включая IPv6. Маршрут HAOS по умолчанию сохраняется.
- Режим `force` выбирает VPN-выход или балансировщик, режим `native` следует правилам профиля и допускает прямые подключения. Импортируйте профили и подписки из доверенных источников.
- Для управления выделенным интерфейсом и правилами приложение использует сетевые привилегии хоста. Шлюз стартует из панели вручную. Остановка снимает созданные правила и временные сетевые настройки.
- Для Wi-Fi 5 ГГц нужны поддержка AP и разрешённые каналы в драйвере. DFS требует отдельного разрешения в панели и может задерживать появление сети. Указывайте фактическую страну использования. Настройка региона затрагивает весь Wi-Fi хоста.

## Управление выделенным портом в HAOS

В режиме Ethernet с DHCP RuslanXRAY временно снимает выделенный интерфейс с управления NetworkManager через системную шину HAOS. Приложение назначает адрес шлюза и запускает DHCP. При остановке NetworkManager снова управляет портом. Выберите порт, который не используется для подключения самого HAOS, и подключите его к WAN отдельного роутера или к точке доступа. Для режима ручной настройки адресом интерфейса управляет HAOS.

## Доступ между локальными подсетями

В дополнительных настройках сети включите **Разрешить доступ между локальными подсетями**. На основном роутере добавьте статический IPv4-маршрут к клиентской подсети через WAN-адрес HAOS. Например, маршрут к 192.168.50.0/24 через 192.168.0.89. Лучше закрепить WAN-адрес HAOS в DHCP основного роутера.

Устройства смогут обращаться друг к другу по IPv4. Если на втором порту установлен ещё один роутер, для доступа к каждому его клиенту используйте режим точки доступа. Он должен подключать клиентов к подсети RuslanXRAY. Широковещательное обнаружение и mDNS между подсетями не пересылаются. Интернет клиентов обрабатывается Xray по выбранному профилю.

## Wi-Fi 5 ГГц и no-IR

Флаг no-IR запрещает адаптеру начинать передачу, в том числе рассылать маяки Wi-Fi. Смена глобального региона не снимает ограничения прошивки у адаптеров с собственным регуляторным доменом. Для Intel с iwlmvm проект Linux Wireless указывает поддержку AP на 2,4 ГГц и ограничение 5 ГГц из-за LAR. [Документация iwlwifi](https://wireless.docs.kernel.org/en/latest/en/users/drivers/iwlwifi.html)

- Если в настройках есть разрешённый канал 5 ГГц, выберите его. Предпочтите разрешённый канал без DFS для быстрого запуска. Используйте фактическую страну.
- Если выбран разрешённый DFS-канал, дождитесь статуса «Шлюз запущен». Пока hostapd проводит проверку на радары, панель показывает состояние ожидания.
- Если все каналы 5 ГГц запрещены или отсутствуют, используйте отдельную точку доступа в режиме AP/моста через выделенный Ethernet. Отключите DHCP на внешней точке и включите **Ethernet с DHCP** в RuslanXRAY. Внешняя точка раздаёт 5 ГГц, RuslanXRAY выдаёт IP и маршрутизирует трафик через Xray.
- Если сеть видна, но устройство не получает IP, проверьте режим DHCP и убедитесь, что выбранный Wi-Fi-интерфейс выделен для точки доступа. Если IP получен, но интернета нет, проверьте доступность профиля кнопкой **Пинг** и журнал приложения.

## Если что-то пошло не так

| Симптом | Что проверить |
| --- | --- |
| Интерфейс отсутствует | Проверьте, виден ли он в HAOS. Realtek RTL8851BU (`0bda:b851`) требует драйвера ядра, создающего Wi-Fi-интерфейс. Для 5 ГГц можно использовать отдельную точку доступа в режиме моста. |
| Клиент не получает IP | Проверьте кабель, выбранный LAN, режим IP + DHCP и отсутствие другого DHCP-сервера в клиентской сети. |
| Каталог пуст или не обновляется | Проверьте, что URL возвращает полный Xray JSON. Список `vless://` или других URI требует преобразования на стороне поставщика. |
| Требуется остановка | Нажмите **Остановить** на главном экране для снятия правил и остановки сервисов. |
| Шлюз запущен, но интернета нет | Проверьте внешний Xray-сервер, профиль, DNS клиента и журнал приложения в Home Assistant. |

При обращении укажите версию приложения, архитектуру и режим клиентской сети. Удалите из журналов ключи, токены, адреса и ссылки подписок перед отправкой. [Открыть задачу на GitHub](https://github.com/ruslan200065/RuslanXRAY_HA/issues/new)

Для локальной проверки кода выполните `python -m unittest discover -s tests -v` из корня репозитория.
