# RuslanXRAY HA — Xray VPN Gateway для Home Assistant OS

Дополнение HAOS для раздачи интернет-трафика через Xray на выделенный Ethernet-порт либо Wi-Fi-адаптер, который **уже определяется Linux как сетевой интерфейс и поддерживает режим AP**.

- Поддерживаются `amd64` и `aarch64`.
- Панель на русском через Home Assistant Ingress.
- Xray-core, профили Xray JSON, Remnawave-подписки.
- Прозрачный IPv4 TCP/UDP TProxy через nftables; правила создаются при запуске и удаляются при остановке.
- Назначение временного IP и DHCP на отдельном клиентском интерфейсе (`dnsmasq`).
- Режим Wi-Fi AP через `hostapd` для совместимых драйверов. Доступны настройки SSID, WPA2-PSK, диапазона, канала, 802.11n и регуляторного домена.
- Режим boot: manual — VPN-шлюз не запускается автоматически.

**Версия 0.3.14 — чистая рабочая ветка.** Удалены экспериментальные USB-команды, диагностические кнопки и зависимости неполного userspace-драйвера RTL8851BU. Функции Xray, DHCP и стандартного `hostapd` оставлены. Реальный USB Wi-Fi `0bda:b851` **не поддерживается** этой версией, если HAOS не создаёт для него Wi-Fi-интерфейс. Интеграция с этим адаптером без драйвера ядра ещё не готова.

## Установка

1. Home Assistant → Настройки → Приложения → Магазин → ⋮ → Репозитории.
2. Добавить `https://github.com/ruslan200065/RuslanXRAY_HA`.
3. Установить и запустить **Ruslan Xray Gateway**.
4. Открыть веб-панель, добавить Xray JSON или подписку, выбрать профиль.
5. В разделе **Сеть** выбрать WAN (интерфейс с default route) и **отдельный** интерфейс клиентов.
6. Указать режим клиентской сети, сохранить, проверить правила и запустить шлюз.

Не выбирайте интерфейс WAN как клиентский LAN: приложение это запрещает. Перед включением настройте физический доступ к консоли и резервную копию HAOS.

## Вариант 1. Выделенный Ethernet → внешняя точка доступа 5 ГГц

Это практичный способ получить 5 ГГц при отсутствии подходящего драйвера для USB Wi-Fi.

```text
Провайдер / основной роутер
           │
     enp1s0 (WAN)
    Beelink U59 Pro
     Xray + DHCP
     enp2s0 (LAN)
           │
    Внешняя точка доступа (AP / bridge mode)
           │
      Wi-Fi 5 ГГц → клиенты
```

В разделе **Сеть**:

- WAN: интерфейс с default route, например `enp1s0`.
- Клиенты: выделенный Ethernet, например `enp2s0`.
- Сервис клиентской сети: **Ethernet / внешняя Wi-Fi точка доступа: IP + DHCP**.
- Шлюз: `192.168.50.1/24` (пример).
- DHCP: `192.168.50.100 – 192.168.50.200` (пример).

На внешней точке доступа включить режим **AP/моста**, выключить её DHCP и подключить в **LAN**, не WAN, если не используется специальный AP-mode с мостом. Установить отдельный SSID/пароль 5 ГГц. Можно назначить точке управления IP `192.168.50.2` (вне пула DHCP). Клиенты должны получать адрес и шлюз от дополнения, а не от другого роутера.

Для этой схемы не требуется USB Wi-Fi и не нужно менять ядро HAOS.

## Вариант 2. Wi-Fi AP непосредственно на HAOS

При наличии поддерживаемого Wi-Fi-интерфейса выбрать его как клиентский и режим **Wi-Fi AP**. Сам драйвер обязан поддерживать `nl80211` AP и выбранный диапазон. Наличие Wi-Fi-устройства в `lsusb` само по себе **недостаточно**.

Каналы 5 ГГц, помеченные `no-IR` или `PASSIVE-SCAN` драйвером, не могут использоваться как обычная AP точка. Для некоторых драйверов есть DFS и регуляторные ограничения; смена страны не гарантирует снятия `self-managed` ограничений. Выбирайте только фактическую страну применения и разрешённые частоты.

На Beelink встроенный Intel Wi-Fi ранее работал в AP на 2,4 ГГц; его 5 ГГц блокировался драйвером (`no-IR`). USB Realtek RTL8851BU (`0bda:b851`) обнаруживался по USB и отвечал на чтение регистров, но не создавал Wi-Fi-интерфейс без подходящего драйвера HAOS. Не путайте эти два статуса.

## Безопасность и ограничения

- Весь пользовательский IP-трафик обрабатывается на **выделенном** интерфейсе клиента; default route самого HAOS не меняется.
- Режим Xray `force` использует указанный VPN outbound/balancer; `native` сохраняет правила профиля и может разрешать direct.
- IPv6-транзит клиентов блокируется по умолчанию; собственного IPv6 VPN-шлюза нет.
- Дополнение не изменяет постоянную конфигурацию NetworkManager, не перепрошивает Wi-Fi и не загружает драйверы ядра.
- Остановка удаляет созданные сетевые правила и временные сервисы. При жёстком сбое может потребоваться очистка из панели.
- Это приложение использует доступ к сетевым настройкам хоста (`NET_ADMIN`) и должно запускаться только на доверенном HAOS.
- Реальные end-to-end проверки 0.3.14 на вашем сервере, включая TProxy под нагрузкой, ещё не проводились; релиз не следует считать формально сертифицированным.

## Исследование RTL8851BU

Ветка [research/rtl8851bu-userspace](https://github.com/ruslan200065/RuslanXRAY_HA/tree/research/rtl8851bu-userspace) сохраняет предыдущий прототип `libusb`, снимки регистров и подготовку firmware. Этот код **не включён в обычную сборку** и не запускает Wi-Fi AP. Для полноценного userspace AP потребуются перенос USB-драйвера `rtw89`, загрузка firmware, H2C/C2H, MAC/PHY, обработка Wi-Fi кадров и интеграция с AP-стеком.
